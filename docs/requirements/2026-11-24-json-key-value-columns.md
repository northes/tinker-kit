# JSON 表格预览展平键值列

## 背景与目标

JSON 表格预览里，对象数组的每个字段各占一列。`rowData` 这类「一层、且只有键和值」的数组会整列收成可展开的嵌套表，字段名和字段值不能跟 `id` 排在同一行上。

目标：在对象数组横表里，把符合条件的键值数组摊成列。`id` 仍是普通列，列名键的值做表头，值键的值做单元格。此行为放在「显示设置」里，默认打开，并记住开关。

## 需求条目

1. 「显示设置」增加复选框「展平键值列」（英文 `Flatten key-value columns`），下方一行说明：只影响表格预览；对象数组里、恰好两个标量键的数组会摊成列。中英文资源同步。默认打开。
2. 开关写入应用配置，字段 `jsonFlattenKeyValueColumns`。读取时先套 `defaultConfig` 再反序列化，因此旧配置缺这个字段时仍为打开。用户显式关闭后保持关闭。前端首帧占位与 Go 默认值一致，并用 `!== false` 把缺省当成打开。
3. 打开时，只在对象数组横表（根就是该数组，或从竖表展开进来的嵌套横表，含流水线小结果预览）里就地展平。根对象竖表不改。关掉时，这些表恢复现在的嵌套展开，不留第二套列。
4. 某个数组字段要展平，必须同时满足：
   - 每一行上，该字段要么不存在，要么是空数组，要么是「每个元素都是对象、键集合完全相同、恰好两个键、值全是标量（`null` / `string` / `number` / `boolean`）」的数组。
   - 任一行是 `null`、非数组、含非对象元素、第三个键、对象或数组值、或数组内列名重复，则该字段整列不展平。
   - 列名键：在每个非空数组内，该键的值都是非空字符串且互不重复。空字符串不算列名，不裁剪空白。
   - 两个对象键里只有一个能当列名时，用它当列名，另一个当单元格。
   - 两个都能当列名时：至少要有两个非空数组；其中一个键在各行的取值集合完全相同，另一个键的取值集合至少有一行不同。集合相同的那个是列名。集合都相同、或都不同、或只有一个非空数组时，不展平。
5. 表头用列名键的值本身（如 `attendanceDate`），不带 `rowData.` 前缀。与已占用列名冲突时，只把冲突的展平列改成 `数组字段名.列名`（如 `rowData.id`）。已占用列名包括不展平的同级字段，以及已经排进去的展平列。加上前缀后仍然冲突，则这一个数组字段整列不展平。
6. 展平列插在原数组字段的位置。顺序取第一条非空数组里列名的出现顺序；后面行首次出现的列名，按该行数组里的顺序追加。某行没有该列名、或该行没有这个数组字段时，单元格与 `null` 一样显示「—」，不要显示「不支持的值」。值是空字符串时仍显示空字符串。
7. 同一行上有多个符合条件的数组字段时，各自展平。单元格仍走现有时间格式化：用列名键的原始值（如 `signInTime`）当字段名，不用加了前缀的表头，也不改原始 JSON。行号列、数字列的既有判定保持不变；展平单元格按取出来的值判定是否为数字列。
8. 判定与列计划做成纯函数，放在 `frontend/src/lib/json-table-pivot.ts`，由表格预览在开关打开时调用。不要在渲染层复制一套判定。

## 已定决策

- 判定按需求条目 4，不放宽到「多于两个键」，也不在「只有一行且两个键都是不重复字符串」时展平。
- 列名用值本身，仅在和已占用列名冲突时加数组字段前缀；前缀后仍冲突则该数组字段不展平。
- 最外层对象仍是竖表。用户展开到 `pageData` 这类对象数组后才看到展平列。根就是这种对象数组时直接展平。
- 开关持久化，默认打开。配置键 `jsonFlattenKeyValueColumns`，与 `jsonAutoFormatOnFill` 同一条配置流：`Config` 默认值、`default-settings.ts` 首帧占位、`App.tsx` 传入 JSON 工具并 `setSettings` 保存。不另建本地存储。
- 不存在的字段与空数组一样视为符合，不因此阻止其它行展平。`null` 或其他非数组则整列不展平。
- 时间格式化看原始列名，不看前缀表头。
- 文案 key：`jsonTool.flattenKeyValueColumns`、`jsonTool.flattenKeyValueColumnsHint`。对话框沿用现有复选框和说明文字的排法，不新增样式文件。

## 非目标

- 不把根对象竖表自动换成内层宽表，也不隐藏 `code`、`desc`、`totalCount`。
- 不改流水线后端分页大表（`ReadPipelineTablePage` 那条路径）。小结果仍走前端表格预览，会展平。
- 不修改原始 JSON，不把普通对象按点路径展平。
- 不把作为当前表数据源的键值数组再透视成一行。`[{fieldName, fieldValue}]` 这种表仍是两列。
- 不加命令面板入口。格式化时间和不可见字符这次也不补持久化。
- 不改表格的行号、斑马纹、表头样式和展开状态的保存方式。

## 验收标准

1. 示例中的 `pageData` 横表在开关打开时，每行是 `id` 加上 `rowData` 里 `fieldName` 的值；单元格是对应的 `fieldValue`。`null` 显示「—」。
2. 关掉开关后，同一张表恢复为 `id` 与可展开的 `rowData`，与现在一致。
3. 下列输入不展平该数组字段：元素含第三个键、值里有对象或数组、列名在同一数组内重复、列名有空字符串、两个键都是不重复字符串且只有一行、两个键的取值集合在多行间都变或都不变。
4. 多行里只有 `fieldName` 的值全体不重复，`fieldValue` 有重复或 `null` 时要展平。某行缺少该字段或是空数组时，其它行仍展平，缺的单元格为「—」。
5. 与同级字段重名的列显示为 `rowData.id` 这种前缀；前缀仍冲突时该字段保持嵌套列。后出现的列名追加在已有展平列之后。
6. 打开时间格式化后，`signInTime` 这类列名仍被格式化，原始 JSON 不变。
7. 重启后开关保持上次的选择；旧配置没有该字段时为打开。
8. 中英文都有开关和说明。`frontend/bindings/` 只由 `wails3 task common:generate:bindings` 生成。
9. 纯函数测试覆盖条目 3 至 5 的正反例。
