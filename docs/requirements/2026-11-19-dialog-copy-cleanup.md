# 对话框文案清理

## 背景与目标

现有各类 Dialog 的副标题（`DialogDescription`）与框内说明段落普遍采用「一句话把动作、实现方式和结果都说一遍」的写法，读起来像模板化说明文，且常与标题、字段标签重复。典型例子是镜像管理的「重命名镜像」「复制到新 Tag」：标题已说明动作，描述又复述一遍「为 N 个镜像生成新名称」「为 N 个镜像创建新的 Tag，原 Tag 将保留」。

目标是让对话框标题承担「做什么」，字段标签与占位符承担「填什么」，只在确实会影响用户决策时保留一行说明。

## 需求条目

1. 清理范围：所有 `Dialog`／`AlertDialog` 的标题与描述、以及对话框内部的灰色说明段落；不改错误提示、字段占位符与工具页内的提示。
2. 能靠标题说清的描述整条删除，删除后不补替代文案，同时移除失去描述的 `DialogDescription` 元素与未使用的导入。
3. 操作后果只保留破坏性的一种（例如重命名会删除原 Tag），「原 Tag 将保留」「最多重连 5 次」「默认端口 123」这类非破坏性细节不再写进描述。
4. 需要保留上下文（对象名、目标路径）的地方，描述只留上下文本身，不再套「选择……的方式」「勾选……中需要……」的句式。
5. 中英资源同步修改，删除的 key 从 `zh-CN.json` 与 `en-US.json` 一并移除。
6. 措辞顺带修正明显别扭的标题，例如「选择要挑选的容器」改为「挑选容器」。

## 已定决策

- 范围：对话框标题 + 描述 + 框内说明段落；不含错误提示与占位符；`ConfirmDialog` 正文只做同类清理，破坏性警告保留。
- 力度：能靠标题说清的整条删除，而不是保留后压成一句。
- 事实信息：只保留破坏性后果。
- 交付：直接改代码与资源，最后给「原文 → 新文／已删除」清单。

## 非目标

- 不调整对话框布局、间距、按钮位置，不改 `DialogContent` 宽度与滚动结构。
- 不改工具页（非对话框）内的提示文案与空状态文案。
- 不改错误提示、校验提示与 toast 文案。
- 不新增或重命名 locale key（除删除与改写既有 key 文本）。

## 验收标准

- 逐条核对清单，以下对话框不再出现与标题重复的描述：镜像推送／批量推送／重命名（仅保留删除原 Tag）／复制到新 Tag／拉取镜像、镜像导入确认、SSH 文件操作、新建文件与文件夹、HTTP 请求设置、SSH 配置列表与表单、应用内 SSH 主机指纹列表与编辑。
- `zh-CN.json` 与 `en-US.json` 的 key 结构保持一致，删除的 key 在两个文件里都不存在，且没有残留引用。
- 删除描述后的对话框仍能正常打开与提交，键盘提交（回车）不受影响。
- 类型检查与构建通过。

## 待定问题

- 无。
