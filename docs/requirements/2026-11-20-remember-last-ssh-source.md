# 新建标签沿用上次连接的来源

## 背景与目标

这些工具的来源下拉都支持 SSH 主机：文件管理、镜像管理、端口占用、网络测试、容器与服务，端口转发则只在「新建转发」表单里选来源。除文件管理外，新建标签时一律默认选来源列表首项（容器与服务默认「本机」），用户每次都要重新点回自己正在用的那台主机。

文件管理已改成「新建标签沿用上次连上的来源」。目标是把这套逻辑推到所有支持 SSH 的工具：本次运行里，某个工具最近一次选中的来源，就是这个工具下一个新标签的默认来源。

## 需求条目

1. 文件管理（`ssh-files`）：新建标签默认上次连上的来源（已实现，本次只做与共享实现的统一）。
2. 镜像管理（`image-manager`）：新标签默认上次选中的来源，含「本机」。
3. 端口占用（`ports`）：新标签默认上次选中的来源，含「本机」。
4. 网络测试（`network-test`）：新标签默认上次选中的来源，含「本机」。
5. 容器与服务（`service-manager`）：新标签默认上次选中的目标，含「本机」。
6. 端口转发（`port-forwards`）：「新建转发」表单的来源默认值取上次用过的转发来源。
7. 记忆只存在内存里：不写 `localStorage`，不进持久化 Config，重启后回退原有默认（列表首项 / 本机）。
8. 记忆按工具隔离：各工具只记自己的上次选择，互不影响，也不跨工具按 SSH 主机共享。
9. 记忆对已有标签无副作用：已打开标签的当前来源不因其他标签的选择而改变，只有新标签读取记忆。
10. 上次的来源已被删除、或指向的 SSH 配置已失效时，回退到该工具原有默认（列表首项 / 本机），不出现空选。

## 已定决策

- 记忆粒度：每个工具各记各的，取本工具最近一次选中的来源；不做「全局按 SSH 主机共享」。
- 「本机 / local」也是来源，同样纳入记忆：上次选本机则新标签默认本机。
- 端口转发没有工具栏来源选择，记忆作用在「新建转发」表单的来源初始值上，不改已保存的转发规则。
- 容器与服务只记当前查看的目标（`targetID`）；多选「已挑选」成员不纳入记忆。
- 记忆不落盘：与「工作区标签和其中的输入只活在本次运行」的既有约束一致。
- 实现上共用一个小工具（本次运行内的来源记忆），各工具不再各写一份模块级变量；文件管理一并改用该实现。

## 非目标

- 不改来源管理（增删改来源、SSH 配置表单）与来源列表顺序。
- 不改各工具的扫描、查询、任务和事件逻辑，不改标签标题里的主机名显示。
- 不改 `Config` 持久化结构，不新增设置项。
- 不把「上次来源」同步到托盘、命令面板或其他工具。

## 验收标准

- 在同一工具里选中某来源后，新建同工具标签，来源下拉等于该来源（文件管理、镜像管理、端口占用、网络测试、容器与服务逐个覆盖）。
- 上次选「本机」时，新建标签默认「本机」。
- 关闭该标签再新建，仍沿用上次来源；重启应用后回到列表首项 / 本机。
- 删除上次使用的来源（或删除其 SSH 配置）后再新建标签，回退到列表首项 / 本机，不出现空选或报错。
- 已打开标签的当前来源不受其他标签选择影响。
- 端口转发：改过来源后新建转发，表单来源预填上次用过的来源；该来源被删时回退首项。
- 前端类型检查（`frontend` 下 `tsc --noEmit`）通过；已有前端单测通过；改动文件符合 prettier。
