# SSH 配置选择改为可输入 combobox

## 背景与目标

「新增目标主机」表单里的 SSH 配置下拉由纯 `Select` 实现，配置一多就只能靠滚动和肉眼找，无法按键名或主机定位。目标是把共享组件 `SSHProfileSelect` 换成可输入过滤的 combobox：输入即过滤，选中即写入原有 `sshProfileID`，不改变任何调用方的数据模型。

## 需求条目

1. `frontend/src/components/SSHProfileSelect.tsx` 由 `Select` 改为 Base UI `Combobox`，复用现有 `frontend/src/components/ui/combobox.tsx` 封装。共享组件改一次，所有使用处同时生效：端口工具、端口转发、服务管理、SSH 文件、镜像管理的新增目标主机表单，以及网络测试工具「来源」头部字段。
2. 输入内容作为过滤条件：按配置名称、`user@host:port`、本机别名（`originAlias`）匹配，忽略大小写。
3. 选项行显示两行信息：第一行为配置名称；第二行为等宽字体的 `user@host:port`，与管理面板列表的信息层级保持一致。
4. 没有任何匹配项时，列表内显示「没有匹配的 SSH 配置」空态；不产生自由值，输入内容不会被当作配置值。
5. 输入过滤后未选中任何项时，输入框内容还原为当前已选配置的名称（没有选中则为空），即取消过滤不会留下脏文本。
6. 已选配置在配置列表里已不存在时，仍保留现有「SSH 配置已失效」项，行为不变。
7. 组件右侧的齿轮按钮保留，点击仍打开 SSH 配置管理面板并带上当前选中 id。
8. `profiles` 为空时保持现有表现：禁用选择并显示「暂无 SSH 配置」。
9. 键盘操作沿用组件能力：上下移动高亮、回车选中、Esc 关闭列表并还原输入。

## 已定决策

- 改动落在共享组件 `SSHProfileSelect`，不为个别调用方分支或另起第二套选择器，因此所有使用处一并变成 combobox（含网络测试工具头部字段）。
- 只做过滤，不做自由输入值，也不做内联新建 SSH 配置；值仍然是已存在配置的 `id`。
- 匹配范围包含名称、`user@host:port`、本机别名；选项行显示名称与等宽 `user@host:port` 两行。

## 非目标

- 不修改 SSH 配置的数据结构、Go 服务、Wails bindings 与配置文件格式。
- 不修改 SSH 配置管理面板（`SSHProfileManagerDialog`）的列表、搜索与表单。
- 不修改各工具 `draft.sshProfileID` 的写入方式与「选择后回填名称」的现有逻辑。
- 不新增「使用输入内容新建配置」之类的新入口。

## 验收标准

1. 上述 6 个使用处都显示为可输入的 combobox，外观沿用项目现有 combobox 样式（`InputGroup` + 下拉浮层），宽度按各自容器自适应。
2. 输入名称片段、host、用户名或端口片段都能命中对应配置；大小写不敏感。
3. 选中某项后 `draft.sshProfileID` 与调用的 `onSelect(profile)` 与改动前一致，退回下拉仍显示该配置名称。
4. 输入无匹配内容时显示「没有匹配的 SSH 配置」；点击组件外或按 Esc 后输入框恢复为已选配置名称。
5. 已选配置被删除（或草稿引用了不存在的 id）时仍显示「SSH 配置已失效」且不报错。
6. `profiles` 为空时组件为禁用态并显示「暂无 SSH 配置」，齿轮按钮仍可打开管理面板。
7. 新增或调整的用户可见文案在 `zh-CN.json` 与 `en-US.json` 同步存在；无新增 key 时复用现有 key。
8. 类型检查与前端构建通过（按 `project-validation` 以 diff 选择实际命令）。
