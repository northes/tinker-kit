# SSH 文件：未知后缀文件点击即嗅探文本

## 背景与目标

`frontend/src/components/ssh-files/model.ts` 的 `isEditableTextFile` 只按**文件名/后缀白名单**判断能否进编辑器：后缀在代码/文本扩展名集合，或整名命中 `dockerfile`、`makefile`、`readme`、`.env`、`.env.*` 等。其余文件（无后缀的 `myconfig`、`KEYFILE`、`notes.backup` 之类）单击直接走 `downloadSelected` 下载，即使它其实是纯文本。

用户希望这些「猜不出来」的文件也能用编辑器打开，而不用先下载再打开；同时希望对任意非目录文件保留一个**显式**的「用编辑器打开」入口，由用户自己决定尝试，打不开就直接报错。

后端已经具备判定能力，无需新增接口：`sshfiletext.go` 的 `readRemoteText` 会 `Lstat` 检查大小（`remoteTextFileLimit = 2 << 20`，超限报 `textTooLarge`，不会传输大文件）、拒绝非 regular file（`textNotRegular`）、读后校验 `utf8.Valid(data)` 且 `containsNul(data)` 为假（`textInvalidEncoding`），并通过 `acquirePersistentSFTP` 复用长连接。

目标：文件名判不出文本时，把「实际读一次」当作嗅探；读成功就打开编辑器，读失败按原因回退下载或显示错误。

## 需求条目

1. **单击未知后缀文件先试编辑器**：单击文件名时，若 `isEditableTextFile` 为真，行为完全不变（立即挂载编辑器弹窗并显示 loading）；若为假且条目不是目录、不是符号链接，则先尝试读取，读成功即打开编辑器，判定不是文本则自动回退到现有的下载流程。
2. **嗅探复用编辑器读取，不新增后端接口**：嗅探就是编辑器自身的那一次 `ReadRemoteTextFile(sourceID, path, 0)`；不得为此新增 Go 侧接口、不得重新生成 bindings、不得为同一文件读两次。
3. **判定前不显示弹窗**：未知后缀文件在首次读取结果返回前不渲染编辑器弹窗（不出现「弹窗闪一下又关掉」）。已知文本文件的弹窗时序与 loading 表现保持现状。
4. **读取期间有行内指示**：等待判定期间该行显示可见的忙碌指示（沿用现有 `Spinner` 用法），不阻塞其它行、不加全局遮罩。
5. **判定规则沿用现有后端限制**：`≤ 2 MiB`、合法 UTF-8、无 NUL 字节、仅 regular file。不额外引入可打印字符比例等启发式。
6. **只有文本判定失败才回退下载**：`errors.sshFile.textInvalidEncoding`、`errors.sshFile.textTooLarge`、`errors.sshFile.textNotRegular` 三种错误视为「不是文本」，关闭这次编辑并调用现有 `downloadSelected([entry.path])`，回退过程不额外弹 toast（下载自身既有的提示保持原样）。其它错误（连接失败、权限、超时、路径不存在等）照旧在编辑器内显示错误，不回退下载。
7. **目录与符号链接不变**：目录仍导航进入；符号链接仍不进编辑器、单击直接下载。
8. **收藏夹跟随同一规则**：收藏资格从「目录或已知文本文件」放宽为「目录或非符号链接文件」；打开收藏时，目录导航，非符号链接文件按第 1 条同样嗅探。判定不是文本时沿用现有 `sshFilesTool.favoriteFileNotEditable` 提示，符号链接仍走该提示。
9. **右键新增「用编辑器打开」**：文件行的右键菜单为 `!entry.isDir && !entry.isSymlink` 的条目新增该项（已知文本文件、压缩包、图片、无后缀文件都显示），点击后**跳过嗅探**直接挂载编辑器；非文本就读不出来，错误按编辑器现有方式显示在弹窗内（`textInvalidEncoding` / `textNotRegular`），**不回退下载、不自动关闭、不额外弹 toast**。超过 2 MiB 时沿用编辑器现有的「超限转 tail 查看」行为。
10. **该项只作用于右键的那一行**：即使已多选多行，也只打开右键的那一个文件（编辑器一次只能开一个）。
11. **菜单位置与文案**：单独一项，放在「复制路径/收藏」分组之后、分隔线之后的操作组首位（复制/移动/重命名/下载之前），图标沿用现有 14px `weight="regular"` 规格；文案走 i18n，`zh-CN` 为「用编辑器打开」，`en-US` 同步补齐（如 `Open with editor`）。

## 已定决策

- **单击即试编辑器**，而不是只在右键菜单增加入口：单击是唯一的主入口，多一个菜单项会让「能加收藏却不能单击打开」的不一致继续存在。
- **复用编辑器读取当嗅探**：读一次既完成嗅探又不浪费——成功时编辑器直接用这次结果。代价是二进制文件多 1–2 个往返（持久 SFTP 会话，200ms 链路约 0.3–0.8s）后才开始下载；相比新增 8KB 嗅探接口，后者会让**最常见的文本文件**每次都多一个往返，并且要重新生成 bindings。
- **判定前不显示弹窗**，改为行内 spinner：避免二进制文件出现弹窗闪动，同时保证单击不是「没有反应」。
- **沿用后端现有 2MB / UTF-8 / 无 NUL 规则**：与编辑器自身的可编辑边界一致，行为可预测；不额外加可打印字符比例，避免误拒含控制字符的合法文本。
- **回退下载不弹 toast**：用户感知等同于现在的「单击未知文件开始下载」，不产生噪音。
- **只对文本判定类错误回退**（`textInvalidEncoding` / `textTooLarge` / `textNotRegular`）：连接类错误直接回退会掩盖真实故障，并把「下载失败」变成用户看到的第二重错误。
- **收藏资格与打开规则对齐**：收藏范围放宽到所有非符号链接文件，否则「打开时可以嗅探、收藏时却说不可编辑」自相矛盾。
- **不做「非文本」结果缓存**：回退下载本身是更重的一步，再为它维护一份会话级缓存不值得；文件后来变成文本时也不会被旧结论挡住。
- **新增显式「用编辑器打开」菜单项**：隐式嗅探会静默回退下载，用户想「明知可能不是文本也要试一下」时需要一个不被拦截的入口；显式入口失败即报错，正是它与单击路径的差别。
- **菜单项对符号链接隐藏**（而非灰显或允许）：保存会写到链接指向的目标文件，保持现有「符号链接不进编辑器」的安全边界，不因这次新增入口而放宽。
- **菜单项对所有非目录文件显示**（含已知文本、压缩包、图片）：按名称隐藏会让菜单项随行闪变，显式入口本就允许失败。
- **多选时只作用于右键那一行**：编辑器单实例，按选中项取第一个会让用户不确定打开的是哪个文件。

## 非目标

- 不改 `remoteTextFileLimit`（2 MiB）、不改后端读取实现、不改 `frontend/bindings/`。
- 不改本地文件（`fileservice.go` / 本地文件视图）的任何打开逻辑。
- 不增加右键「直接下载」以外的下载入口调整；下载仍走现有 `downloadSelected`。
- 不为右键菜单增加批量打开（多选只作用于右键那一行）。
- 不引入文件内容猜测的启发式（可打印比例、魔数表、mime 探测）。
- 不改变 `remoteFileIcon` 的图标判定。
- 不改变符号链接、目录、压缩包、批量操作与搜索结果的既有行为。

## 验收标准

1. 单击 `myconfig`（无后缀、纯文本）→ 不出现下载，编辑器打开并显示内容；全程只有一次 `ReadRemoteTextFile` 调用。
2. 单击无后缀二进制（如 `payload`，含 NUL 或非 UTF-8）→ 不出现编辑器弹窗，直接开始下载；无额外 toast。
3. 单击超过 2 MiB 的无后缀文件 → 不回退为「读取大文件」，直接进入下载。
4. 单击已知文本文件（如 `app.json`）→ 与改动前完全一致：弹窗立即出现并显示 loading，无行内 spinner。
5. 未知后缀文件读取期间出现行内忙碌指示，其它行与表格滚动、勾选、批量操作不受影响。
6. 未知后缀文件读取遇到连接错误 → 编辑器显示错误信息，不触发下载。
7. 符号链接仍不进编辑器、单击直接下载。
8. 收藏夹可添加任意非符号链接文件；打开未知后缀的收藏文件按第 1、2 条表现；判定不是文本时提示 `sshFilesTool.favoriteFileNotEditable`。
9. 右键任意非目录、非符号链接文件 → 出现「用编辑器打开」；单击该项，未知后缀的二进制文件直接弹出编辑器并显示 `textInvalidEncoding` 一类错误，**不转为下载**。
10. 右键符号链接或目录 → 无该项；已多选多行时右键其中一个文件 → 只打开右键的那一个文件。
11. 现有前端 dom 测试、类型检查与 `wails3 task` 相关构建通过；新增文案（含菜单项）必须同时补齐 `frontend/src/locales/zh-CN.json` 与 `en-US.json`。
