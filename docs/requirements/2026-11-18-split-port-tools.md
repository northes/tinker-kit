# 拆分端口占用与端口转发

状态：已对齐。实现时以本文「已定决策」与「需求条目」为准。

## 背景与目标

现在「端口工具」（`ports`）是一个工具，内部用标签切换「端口占用」和「端口转发」。两边共用一份端口来源，转发规则、扫描和列宽都写在这一份配置里。

目标：拆成两个工具。端口占用只扫描端口，端口转发只管理 SSH 转发。来源列表分开。转发全局只有一份列表、一批隧道，并且同时只能开一个标签。

## 需求条目

1. `ports` 改名为「端口占用 / Port usage」，只保留现在的端口扫描页，去掉工具内部的「端口占用 / 端口转发」标签。新增工具 `port-forwards`，名为「端口转发 / Port forwarding」，只保留现在的转发列表和增删改、启停、拖拽排序。
2. 简介：占用是「检查本机与 SSH 主机上的端口占用 / Inspect ports on this machine and SSH hosts」；转发是「经 SSH 做本地或远程端口转发 / Forward ports locally or remotely over SSH」。占用沿用插头图标，转发用双向箭头。中英文一起改。
3. 设置里的工具列表：已有 `ports` 保持原位置和启用状态。`port-forwards` 默认启用，插在该用户列表里 `ports` 那一项的后面；用户改过顺序也紧跟 `ports`，不追加到末尾。`ports` 不在列表里时，先按现有规则补上 `ports`，再把 `port-forwards` 放在它后面。
4. 命令面板只有两个打开命令（端口占用、端口转发）。不把这两个工具加入托盘剪贴板识别，也不新增刷新、新增、管理来源等动作命令。
5. 端口来源各管各的。占用继续使用现有 `portSources`，内容不迁移。转发使用新的来源列表，缺省以及旧配置没有该字段时只有「本机」。不从占用复制、不搬走仍被转发引用的 SSH 来源。
6. 转发不能选择本机作为隧道主机。已有规则原样保留：来源 ID 不在转发来源列表里时，列表和筛选仍显示这些规则，主机列显示「主机已失效」，不能启动。重新添加 SSH 来源会得到新 ID，不自动接回旧规则。要再启动，须先在转发里添加 SSH 来源，再编辑规则改选它。读取、保存和导入旧配置都不得因为这种悬空来源拒绝整份配置，也不得删掉这些规则。
7. 转发页在「新增转发」旁增加按钮「管理来源 / Manage sources」，对话框与占用页的来源管理相同，只读写转发自己的列表。本机在列表中且不可删除。新建和编辑转发的主机下拉只列出这份里的 SSH 来源，底部沿用「管理 / Manage」。没有 SSH 来源时下拉里只有「管理」，表单仍能打开，但没选主机不能保存。删掉仍被规则引用的来源后，规则保留并显示「主机已失效」。
8. 改占用的来源不断开正在跑的转发。新增、编辑或删除转发来源会断开全部正在跑的隧道。修改 SSH 配置仍断开全部正在跑的隧道（保持现在的行为）。只改转发规则本身时，仍只同步被改写或删除的那几条，不停掉其它隧道。
9. 端口占用可以开多个标签。每个标签自己选主机、自己扫描。选中的来源是有效 SSH 主机时，标签标题为 `[主机名]端口占用`，序号仍在工具名后（`[主机名]端口占用 2`）。主机名用该标签主机下拉的显示名。本机、或该来源引用的 SSH 配置已失效时不加前缀。手动重命名过的标签只显示自定义名。
10. 端口转发全局只有一份列表和同一批隧道。同时只能有一个转发标签。已经有时，从命令面板、空白标签或工具网格再打开都切到那一个，不新开、不提示；当时的空白标签留着不动。还没有时按普通工具：当前是空白标签就地变成它，否则新开一个。关掉这个标签不停止已在跑的隧道。转发标签不加主机前缀，只显示「端口转发」和序号。
11. 两个页面除本文点名的差异外，保持现在各自那一页的交互：扫描的取消与换主机、转发的筛选、拖拽排序、重连、列宽持久化、搜索框不出现清空按钮、表头样式。占用列宽仍按占用的主机保存，转发列宽仍是不分主机的一份。

## 已定决策

### 工具身份

- 占用 ID 保持 `ports`。转发 ID 为 `port-forwards`。
- 页面上已有的按钮、表头、空态、确认框文案不改。新的用户可见文案只有工具名、简介、打开命令，以及转发页的「管理来源 / Manage sources」。
- 占用的搜索关键词去掉「转发 / forward」；转发的关键词覆盖端口转发、SSH、tunnel。两边都还能被「端口」找到。

### 来源与配置

- 新字段与占用的 `PortSources` 使用同一个来源结构。JSON 名为 `portForwardSources`。规范化与占用相同：始终保留一条本机，只接受 SSH 来源，本机不可删。
- 转发规则仍在 `portForwards`。悬空 `sourceID` 继续保留，界面显示现有的「主机已失效」。`sourceID` 为空或 `local` 的规则仍然非法，按现有规范化丢弃。
- 设置页保存时不得用旧快照覆盖转发来源，处理方式与现在保护 `portSources`、`portForwards` 相同。
- 导入校验不再要求转发的 `sourceID` 必须存在于占用或转发来源列表。转发来源自身仍然要结构合法，SSH 来源必须引用现存的 SSH 配置。

### 隧道生命周期

- 配置变更里，占用的 `portSources` 变化不调用全量停止。
- `portForwardSources` 变化则停止全部正在跑的隧道。
- `SSHProfiles` 变化仍停止全部正在跑的隧道。
- 仅 `portForwards` 变化时保持现在的按条同步，不因为回调停掉未改动的隧道。
- 转发不随应用启动自动拉起，关掉标签也不停止。

### 标签

- 打开转发的所有入口都走同一条规则，包括命令面板和空白标签网格。已在当前标签上时再次打开是空操作。
- 占用的标题走现有 `useWorkspaceTabTitle`：只上报主机显示名，不拼工具名和方括号。转发工具不上报主机名。
- 禁用工具时仍用现有的「关掉它的 N 个标签并禁用」。不因为转发只能开一个而改这套确认。

### 顺序

- 新安装的默认顺序里，`port-forwards` 紧跟 `ports`，在 `network-test` 之前。
- Go 的配置规范化和前端补全缺失工具时都按需求条目 3 插入，不能只追加到列表末尾。

## 非目标

- 不把扫描和转发拆成两个 Go 服务，不改扫描命令、隧道实现和重连次数。
- 不把已有 SSH 来源复制或迁移到转发，也不在新建来源时自动对上旧规则。
- 不限制端口占用能开几个标签，不给转发标签加主机前缀。
- 不把这两个工具加入托盘识别，不新增打开以外的命令面板动作。
- 不改表头样式、搜索框清空按钮、`default-light` / `default-dark`。
- 不改占用页来源管理的入口（仍在主机下拉里的「管理」）。

## 验收标准

- 工具目录、命令面板和空白标签里是两个工具，名字和简介与需求条目 2 一致；占用页没有转发标签和转发操作，转发页没有端口扫描。
- 已有配置加载后：占用的来源列表不变；转发来源只有本机；原来指向 SSH 来源的转发还在，显示「主机已失效」，启动失败且配置仍能保存、导入。
- 在转发里添加 SSH 来源后，编辑旧规则改选该来源可以再启动。新建转发在没有 SSH 来源时表单能开但不能保存。
- 用户把 `ports` 排到列表前面时，新出现的 `port-forwards` 紧跟在它后面且为启用；`ports` 原来是停用则仍然停用。
- 两个端口占用标签可以各选各的主机并各自扫描。选中 SSH 主机时标题为 `[主机名]端口占用`；本机或 SSH 配置已失效时无前缀；重命名后只显示自定义名。
- 已有转发标签时再次打开只是切过去，空白标签还在；没有时从空白标签打开会就地变成转发。关掉转发标签后隧道仍在，再次打开列表和运行状态还在。转发标题始终是「端口转发」加序号。
- 只改占用来源时，正在跑的转发不断。新增、编辑或删除转发来源后，正在跑的转发全部停止。只改一条转发规则时，其它隧道不停。修改 SSH 配置仍会停掉全部转发隧道。
- `go test ./...` 与前端相关检查通过。Go 导出变化后的 `frontend/bindings/` 是重新生成的，不是手改。
