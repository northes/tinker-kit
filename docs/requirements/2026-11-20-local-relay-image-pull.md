# 拉取镜像可选本机中转

状态：已对齐，待实现。实现时以本文「已定决策」与「需求条目」为准。

## 背景与目标

「拉取镜像」只能落在当前选中的来源上。SSH 来源需要远端 docker 自己访问 registry，并且架构解析要走远端的 `docker buildx imagetools inspect --raw`。远端没有可用的 buildx 插件时（例如插件装在用户 home，sudo 以 root 执行后看不到），架构解析直接失败，弹窗只显示整段 docker usage：

```
架构解析失败：远程命令 "docker" 执行失败：unknown flag: --raw ...
```

本机 docker 具备 buildx 与 registry 访问能力。目标：拉取弹窗里可以选择「在本机拉取」，由本机完成拉取和架构解析，再经流式 `docker save | docker load` 把镜像送到目标来源，远端不需要 buildx，也不需要自己访问 registry。

## 需求条目

1. 拉取弹窗新增「拉取位置」二选一：`目标机器` / `本机中转`。只在 SSH 来源显示；本机来源与 Registry 来源不显示、行为不变。
2. 默认值为 `目标机器`，与现状一致。选择只记在本次运行内，不写入配置；重新打开应用回到默认。
3. 选 `本机中转` 时的流程：
   - 架构解析走本机 Docker（本机来源的命令与环境），不再请求目标的 docker。
   - 本机执行 `docker image pull [--platform <p>] <ref>`，进度沿用现有 pull 层进度统计。
   - 成功后本机 `docker save <ref>`，边读边写到目标 SSH 会话的 `docker load`，不落磁盘中间文件。
   - 任务阶段依次为 `pulling`（本机）、`transferring`（save/load），前端沿用现有任务展示，不新增伪精确百分比。
4. 目标上的镜像名沿用用户填写的 ref，不自动 retag，也不改目标来源的命名规则。
5. 本机 CLI 使用全局 `DockerCLIPath`（留空即 `docker`），目标侧继续按该来源现有的 SSH 执行规则（含 sudo 密码、命令前缀、登录 PATH）。
6. 失败与取消：
   - 本机 pull 失败：任务失败，错误沿用现有 pull 失败文案并保留本机 docker 的 stderr 摘要。
   - 传输阶段失败：任务失败，错误带目标 `docker load` 的 stderr 摘要。
   - 取消：中断当前阶段，关闭本机进程与 SSH 会话；已 load 的部分镜像留在目标，不自动清理，也不额外提示。
7. 架构解析失败（选 `目标机器` 且远端缺 buildx）时，错误照旧透传；「本机中转」就是给出的规避手段，不新增自动回退。
8. 新增文案同时写入 `zh-CN` 与 `en-US`。
9. 安全：`docker save` 的输出只走 stdout 到目标 stdin，stderr 单独收集，不混入镜像数据。

## 已定决策

### 结果落点（第一轮）

- 本机只做中转，镜像最终仍在目标来源；不是「切到本机来源再拉」。
- 用户仍可切到本机来源手动拉取，两者并存，不互相替代。

### 传输方式（第一轮）

- `docker save` 直接管道到目标 `docker load`，不生成中间 tar 文件。
- 不新增第二套导出/导入任务通道，复用现有 SSH 流式执行入口。

### 架构解析（第一轮）

- 选本机中转时用本机 docker 解析架构；不请求目标 docker，避免目标缺 buildx。
- 不做「解析失败自动降级为本机」的隐式回退；用户显式选择。

### 界面与记忆（第一轮）

- 弹窗内二选一，默认目标机器，仅本次运行记住上次选择，不写配置。

## 非目标

- 不改 Registry 来源的推送/拉取、镜像同步、导出/导入等其它通道的语义。
- 不为远端补装 buildx，也不把用户的 `DOCKER_CONFIG` 传给 root。
- 不做本机 tar 落盘、断点续传或多阶段重试。
- 不做跨来源批量中转，一次拉取任务仍对应一个镜像。
- 不改变 sudo 密码、命令前缀、登录 PATH 的既有规则。

## 验收标准

- 本机来源与 Registry 来源的拉取弹窗不出现「拉取位置」。
- SSH 来源默认「目标机器」，行为与当前一致：仍走远端 docker pull 与远端架构解析。
- 选「本机中转」后，任务在本机执行 pull；目标机器上没有 buildx 插件也能完成架构解析与拉取。
- 本机中转完成后，镜像出现在目标来源的镜像列表里，名称等于填写的 ref。
- 本机中转全程不产生中间 tar 文件；`docker save` 的 stderr 不出现在目标 `docker load` 的 stdin 里。
- 本机 pull 失败、传输失败、取消三种情况任务状态正确，错误信息包含对应端的 stderr 摘要。
- 关闭并重开应用后，拉取位置回到「目标机器」。
- `wails3 task test:i18n`、`wails3 task test:go`、前端构建无新增失败；`git diff --check` 干净。
