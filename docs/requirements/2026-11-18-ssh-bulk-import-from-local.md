# SSH 配置：从本机一键导入

## 背景与目标

SSH 配置弹窗目前分成「已添加的配置」和「本机 SSH config」两段，本机段需逐条导入，已导入配置在应用内大部分连接字段只读。用户希望简化为单一列表，在「新增配置」左侧增加「从本机导入」，一次解析本机 `~/.ssh/config` 并批量写入应用；同名（`originAlias`）覆盖，导入后在应用内可自由编辑。

## 需求条目

1. **单一列表**：去掉列表中的「已添加的配置」「本机 SSH config」分区标题与本机候选项列表；仅展示应用内已保存的 SSH 配置（搜索、隔行样式、行内铅笔/更多等既有交互保留）。
2. **顶部操作**：列表标题行保留刷新；在「新增配置」按钮左侧增加「从本机导入」；去掉逐条「导入」、行内「从本机更新」、来源「本机导入/手动」徽章。
3. **批量导入行为**：点击「从本机导入」不二次确认，直接执行。解析本机全部可映射 Host：
   - 应用内已存在且 `origin === "ssh-config"` 且 `originAlias` 与本机条目相同：用本机最新参数覆盖连接字段，保留应用内 `id`、显示名称、`jumpProfileID`；计为 **更新**。
   - 本机有、应用内无对应 `originAlias` 的 `ssh-config` 条目：新建配置；计为 **新增**。
   - `origin === "manual"` 的配置 **不** 参与匹配、不被覆盖。
   - 本机已删除但应用内仍保留的历史 `ssh-config` 配置：不自动删除，本次不计入更新。
4. **导入后可编辑**：通过表单保存时，本机导入来源的配置与手动配置同等可编辑（Host/Port/用户/认证/跳板机等），移除「仅可改名称」限制及表单内只读提示。
5. **结果提示**：
   - 本机无可解析配置：`toast` 说明未找到可导入配置（失败/提示样式与项目惯例一致）。
   - 成功：一条 success `toast`，文案形如「已从本机导入：新增 {created}，更新 {updated}」（中英文同步，数字为本次计数，可为 0）。
6. **后端 API**：提供 Wails 批量导入方法（返回 `created`/`updated` 计数及更新后的列表或可由前端 `GetSSHProfiles` 刷新）；单次配置持久化；补充/调整 `go test` 覆盖批量与可编辑保存逻辑。
7. **Bindings**：Go 导出变更后重新生成 `frontend/bindings/`，不手改。

## 已定决策

- 覆盖键：仅 `origin === "ssh-config"` 且 `originAlias` 相同。
- 手动配置不动；不弹确认；本机空用 toast。
- 去掉来源徽章、逐条更新/导入与本机第二列表。
- Toast 一条展示新增与更新条数（用户确认）。

## 非目标

- 不删除本机已不存在的应用内 `ssh-config` 配置。
- 不把手动配置自动改成 `ssh-config` 来源。
- 不改指纹弹窗、工具内 SSH 选择器行为（除列表数据刷新）。
- 不改为逐条仍保留本机预览列表。

## 验收标准

- 弹窗仅一段配置列表；「从本机导入」在「新增配置」左侧。
- 一次点击可导入/覆盖本机全部别名；手动配置不受影响。
- 导入后可修改并保存连接参数。
- 成功/空本机 toast 中英文正确；成功含新增与更新数量。
- `go test` 相关包通过；`wails3 task common:frontend:run SCRIPT=build` 通过。
