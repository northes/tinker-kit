# 主机与来源选择器改用模糊匹配

## 背景与目标

现在的来源 / SSH 配置选择器只做「忽略大小写和分隔符之后的连续子串」匹配。用户记得主机的大致字符但不记得具体分隔位置时搜不出来：输入 `orbz` 找不到 `orb zot`，输入 `l2p` 找不到 `l240_prod`。

目标是让这类输入也能命中：查询字符按顺序出现即可，同时保留原有连续子串的高质量命中优先展示。

## 需求条目

1. 在现有「忽略大小写、空格、下划线和连字符」的归一化基础上，新增按顺序匹配：查询的每个字符在名称中按先后顺序出现即视为命中（`orbz`、`oz` 命中 `orb zot`；`l2p` 命中 `l240_prod`、`l240-prod`、`l240 prod`）。
2. 连续子串命中的排在前，按顺序命中的排在后；同组内保持来源 / 配置原有顺序（稳定排序）。
3. 查询为空时列表顺序与现在一致。
4. 生效范围仅限工具栏来源 / 目标主机选择器（`SourceCombobox`）与 SSH 配置选择器（`SSHProfileSelect`），包含其名称、`user@host:port` 地址与本机别名三处匹配字段。
5. SSH 配置选择器里「配置已失效」这一状态项仍按现有方式参与匹配，且命中时保持排在列表末尾。
6. 匹配与排序逻辑集中在共享模块 `frontend/src/lib/source-search.ts`，不在组件里各写一份。
7. 匹配与排序是纯函数，需有覆盖上述示例的单测。

## 已定决策

- 规则：保留连续子串匹配，额外增加「按顺序出现」匹配；不做完全无序匹配。
- 范围：只改 SSH 主机与来源选择器，其它工具内的搜索框（文件管理搜索、端口列表过滤、镜像与容器筛选等）不动。
- 排序：连续子串命中优先于按顺序命中，组内保持原顺序。

## 非目标

- 不改文件管理、端口占用、镜像管理、容器与服务等工具里其它搜索 / 筛选输入框的匹配规则。
- 不做拼音、缩写、编辑距离等更复杂的模糊匹配。
- 不新增高亮、命中计数等视觉反馈。
- 不改下拉的选中、Esc 取消、Enter 处理与禁用行为。

## 验收标准

1. 在来源 / SSH 配置下拉中输入 `orbz` 或 `oz`，`orb zot` 出现在候选中；输入 `l2p`，`l240_prod`、`l240-prod`、`l240 prod` 都出现在候选中。
2. 同一个下拉里，连续子串命中的项排在按顺序命中的项之前。
3. 清空输入后候选恢复原有顺序。
4. 六个工具（镜像管理、文件管理、容器与服务、端口占用、网络测试、端口转发）的来源 / 目标主机下拉都按新规则匹配；来源 / 目标管理弹窗里的 SSH 配置选择器同样生效。
5. 现有的连续子串行为不回退：`gxprod` 仍能命中 `gx_prod`、`gx-prod`。
6. 类型检查、前端测试与构建通过。

## 待定问题

- 无。
