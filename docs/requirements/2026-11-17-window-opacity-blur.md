# 窗口背景透明度与高斯模糊

状态：已对齐，已实现。本文是「设置里调窗口透明度、开关高斯模糊」的结论。实现时以「已定决策」和「实现约束」为准，不再另做产品决定。

## 背景与目标

窗口现在是一整块不透明底色。Wails 的 `MacBackdropTranslucent` 虽然已经开着，但默认构建下 WKWebView 自身不透明，原生毛玻璃一直被盖住，所以看不出效果。

目标：在设置里给用户两件事——调窗口背景透明度、开关高斯模糊，让桌面能被模糊后透出来，同时不破坏工具内容的可读性。

## 需求条目

1. 设置页「偏好」分类里，在主题模式下面新增一组「窗口外观」，含一个透明度滑块和一个高斯模糊开关。两项只在 macOS 显示；Windows / Linux 不出现。
2. 透明度滑块范围 30%–100%，默认 100%。拖动时背景实时变化，松手写配置。
3. 高斯模糊开关默认开。开：窗口后面是毛玻璃；关：窗口后面是清晰的桌面。两种情况透明度都生效。
4. 透明度 100% 时看不到模糊，但开关仍可正常切换，不禁用、不加说明。
5. 两个值都持久化到应用配置，退出重进后恢复。
6. 不提供模糊强度调节，只有开关。

## 已定决策

### 路线

- 启用 Wails 的 `-tags private_mac_apis` 构建标签，换取 webview 真透明。不加这个标签时 webview 不透明，透明度下面没有东西可透，本需求无法成立。
- 该标签要进 macOS 的开发运行、构建和打包三条路径，否则开发预览和打包产物表现不一致。

### 作用范围

- 整窗一起跟随透明度：标题栏、左右底的缝、内容面板都跟随同一个透明度值。
- 不给内容面板单独设「底衬地板」，滑块下限 30% 就是可读性的下限。
- 术语：模糊只作用于窗口后面的桌面；应用内部的文字、列表、编辑器不做模糊。

### 交互

- 滑块拖动实时预览，松手保存。
- 模糊开关在任意透明度下都可切换。
- 崩溃页保持不透明，不跟随这两项设置。
- 对话框、命令面板、菜单、toast 等浮层保持自己的实底，不受影响。

### 配置

- 新增两个配置字段：`windowOpacity`（整数，30–100，默认 100）、`windowBlur`（布尔，默认 true）。
- Go 层负责范围收敛：小于 30 拉回 30，大于 100 拉回 100，缺失或非法回退默认值。
- 两个值对浅色和深色主题共用一份，不按主题分开存。
- 只有 macOS 使用这两个值；其它平台的配置里保留字段，但不展示、不应用。

## 实现约束

这些是实现时必须遵守的技术边界，不是新的产品决定。

- **透明度的承载层。** 透明度只能落在一层上。每个工具页的根 `.tool-slot` 现在各自铺了一层不透明的 `bg-background`，会盖掉面板的 alpha，必须去掉这层重复铺底，让 alpha 只来自圆角面板本身。全仓其余约 20 处 `bg-background` 大多是按钮、开关、表格这类控件自己的实底，逐处判断后保留，不要为透明度去改控件外观。
- **透明度与模糊各管一段。** 两套机制不能同时按滑块叠加，否则滑块只是在调“界面白不白”。约定：
  - 模糊关：窗口非不透明，原生毛玻璃隐藏，滑块只决定 CSS 叠色 alpha，看到的是锐利桌面。
  - 模糊开：窗口非不透明，原生 `NSVisualEffectView` 的 `alphaValue` 取滑块值，CSS 叠色固定成一成多薄雾（`--window-surface-alpha`），只用来保住标题栏 / 缝 / 面板的层次，不再乘滑块。
  - 不要再用“叠色强度系数”之类的魔法数去拼凑观感。
- **Wails 毛玻璃的坑。** `MacBackdropTranslucent` 只插 `NSVisualEffectView`，不会把窗口设成非不透明；不别开 `setOpaque:NO`，`BehindWindow` 采样不到桌面，只剩材质自带底色（看起来像雾）。切换时必须自己设。
- **CSS 变量。** 新增 `--window-opacity`（0.3–1 的数值），`--chrome` 和面板底色用 `color-mix(... , transparent)` 按它取值。不要直接把 `--background` 改成半透明色再层层叠加，同色叠多层会越来越不透明。
- **原生透明。** 窗口背景色的 alpha 要跟着透明度走：现有的 `Window.SetBackgroundColour(r, g, b, a)` 已经支持 alpha，用它而不是另外新建一条通道。
- **模糊开关。** Wails 没有公开的运行时切换 backdrop 的 API。模糊开关要用 `WebviewWindow.NativeWindow()` 拿到的原生窗口句柄，在 darwin 专用 CGO 文件里控制 `NSVisualEffectView` 的显隐（或用等价的公开 Cocoa 调用），并给非 darwin 平台留同样签名的 stub。不要用重建窗口的方式切换。
- **配置读写路径。** Config 新增字段后必须重新生成 bindings（`wails3 task common:generate:bindings`），前端只用生成的类型，不手写兼容类型。
- **应用时机。** 窗口创建时按初始配置应用一次；之后前端改动时立即应用。不能让重启后才生效。
- **不涉及的平台。** Windows 的 Acrylic / Mica 和 Linux 的等效实现都不在本次范围。

## 非目标

- 不做模糊强度、模糊半径调节。
- 不做按元素、按工具单独的透明度。
- 不做 Windows / Linux 的等效透明与模糊。
- 不改工具页内部布局、工具外观和现有控件样式。
- 不把透明度应用到崩溃页。
- 不新增主题，不改现有 `--background` 的语义。

## 验收标准

- 设置 → 偏好里能看到「窗口外观」组，两个控件位置在主题模式下面。
- 拖到 30% 时能看到桌面并被模糊，文字仍可读；拖回 100% 恢复现在的实心外观。
- 关掉模糊后，同样透明度下看到的是清晰桌面。
- 100% 时开关模糊，窗口外观不变，也不报错。
- 改动后退出重进，两个值都还在。
- 深浅两个主题下都生效，且不出现某个主题下半透明被不透明底盖掉的区域。
- 窗口创建瞬间不闪一下不透明底，也不闪另一种颜色。
- 老配置文件缺少这两个字段时能正常启动，按默认值生效。
- 非 macOS 平台不出现这一组设置。

## 待定问题

无。实现中若发现 `private_mac_apis` 影响签名或打包产物，先停下来说明，不自行改发布流程。

## 变更记录

- 2026-11-17：模糊开时改为原生毛玻璃的 `alphaValue` 承担透明度，CSS 叠色固定薄雾；删掉此前用来压白底的「叠色强度系数」。原因是滑块同时驱动原生与 CSS 两套透明度，表现为「只调白不白、开了模糊才透」。
- 2026-11-17：修正 Wails `MacBackdropTranslucent` 不设 `setOpaque:NO` 的问题，否则毛玻璃只剩材质底色，表现为一层雾而非模糊。
- 2026-11-17（最终）：撤销「滑块驱动原生 alpha」的做法。模糊开即满强度模糊桌面，滑块只表示界面透出多少，两个设置互不耦合。`behindWindow` 才采样窗口背后；`windowBackground` / `contentBackground` 只做桌面取色，不是模糊。
- 2026-11-17：`underWindowBackground` 会发白。它是浅色揭开材质，半透明界面盖上去就被洗白。深色改用 `HUDWindow`，浅色改用 `Popover`，并把外观设在效果视图自己身上。
