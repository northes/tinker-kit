# SSH 远程主机名进入工作区标签标题

状态：已对齐。实现时以本文「已定决策」与「需求条目」为准。

## 背景与目标

工作区标签标题现在是工具静态名（`workspaceTabBaseName` 取工具定义的 `nameKey`），如「镜像管理」「服务管理」。这几个工具都能连远程机器，同时开多个标签时标签栏只显示「镜像管理」「镜像管理 2」，看不出连的是哪台机器。

目标：这些工具的标签标题带上当前主机的显示名，格式 `主机名 · 工具名`。端口转发没有单一「当前主机」，不加。

顺带修掉网络测试的一个不一致：它的主机选择写在全局配置 `NetworkTestSettings.sourceID` 里，多个网络测试标签共用同一个来源，和镜像管理 / 服务管理 / SSH 文件管理的「标签内选择」不一致。改成每标签独立。

## 需求条目

1. 标签标题格式为 `主机名 · 工具名`（中间是空格 + 间隔点 `·` + 空格）；序号规则不变（第 2 个及以后的同类标签在末尾追加 ` 2`），即 `box-a · 镜像管理 2`。
2. 主机名取值顺序：来源自己填的名称 → 它引用的 SSH 配置名 → （仅镜像管理的 Registry 来源）Registry 地址。三者都取不到时不加主机部分。
3. 本机来源不加主机部分，标签保持纯工具名。
4. 覆盖工具：镜像管理、文件管理（原 SSH 文件管理）、服务管理、网络测试。端口转发不加前缀。
5. 主机名随工具内的来源选择实时变化：切到另一台机器，标签标题当即更新；切回本机，主机部分消失。
6. 来源引用的 SSH 配置已被删除（工具内已显示「SSH 配置已失效」）时不加主机部分，回退纯工具名，不把失效状态写进标题。
7. 手动重命名过的标签仍只显示自定义名，不加主机部分、不再拼序号（沿用现有 `workspaceTabLabel` 语义）。
8. 网络测试的主机选择改为标签内状态：新开标签默认取来源列表首项，不再读写配置。Go 侧 `NetworkTestSettings` 移除 `sourceID` 字段并重新生成 bindings；旧配置文件里残留的 `sourceID` 直接忽略，不做迁移。

## 已定决策

### 范围

- 加主机部分的工具：镜像管理、文件管理、服务管理、网络测试。
- 端口转发不加：它没有单一当前主机，只有来源筛选器（默认「全部」）和每条转发各自的来源，筛「全部」时没有任何一个名字能代表这个标签。
- 镜像管理的 Registry 来源也加主机部分，名字取来源名称，名称为空时退回 Registry 地址；只有「本机」来源不加。
- 网络测试的主机选择是全局配置这点不接受，重构为每标签独立（见需求条目 8）。

### 名称与格式

- 「主机名」= 工具内该来源选择器上显示的名字，取不到再回退 SSH 配置名、Registry 地址，所以标签和下拉里看到的名字一致。
- 主机名在前、工具名在后，中间用 ` · `（空格 + 间隔点 + 空格）连接：`box-a · 镜像管理`。
- 间隔点只出现一次，序号仍跟在工具名后：`box-a · 镜像管理 2`。
- 主机名与工具名之间不做额外限长：标签本身已有固定宽度和 `truncate`。

### 工具改名

- 「SSH 文件管理」全局改名为「文件管理」；英文 `SSH Files` / `SSH File Manager` 统一为 `File Manager`。
- 改名范围覆盖所有用户可见位置：工具列表（含描述之外的名字）、命令面板、页面标题、设置里的工具项名称、后台任务中心的工具分组名。
- 标签里不再出现「SSH 文件管理」，避免与主机名重复；连远程时显示 `box-a · 文件管理`，本机时显示 `文件管理`。

### 失效与重命名

- SSH 配置被删除 → 回退纯工具名，不用「配置已失效」之类的文字占位。
- 手动重命名优先级最高：有 `customTitle` 时完全按现有逻辑只显示自定义名。

### 网络测试重构

- `NetworkTestSettings` 里的 `sourceID` 从 Go 结构体删除，`frontend/bindings/` 重新生成（`wails3 task generate:bindings`），不留死字段。
- 新标签默认来源取来源列表首项（通常是「本机」），不记忆上次选择，也不跨标签共享。
- 其余网络测试设置（payload、超时、代理、DNS 等）仍然持久化，行为不变。
- 旧配置里残留的 `sourceID` 不报错、不迁移，读配置时忽略即可。

### 实现通道（供实现时对齐）

- 新增按标签的标题上报通道：`frontend/src/app/workspace-tab-title.ts` 提供 `WorkspaceTabTitleContext` 与 `useWorkspaceTabTitle(hostName: string | null)`。工具在挂载/来源变化时上报**当前主机显示名**（不拼工具名、不拼方括号），卸载或变为 `null` 时清空。
- `App.tsx` 按标签 id 持有这份主机名，并在渲染每个工具的插槽处提供 provider；关闭标签时清掉对应条目。`WorkspaceTabBar` 与重命名对话框的基准名都走同一份数据。
- `workspaceTabBaseName(tab, translate, hostName?)` 负责拼 `主机名 · 工具名`，序号和自定义名仍由现有的 `workspaceTabLabel` / `tabOrdinalLabel` 处理。
- 工具外的渲染（没有 provider）时上报是空操作，不能报错。
- 不新增用户可见文案，不需要新的 i18n key。

## 非目标

- 不改端口转发的标签标题。
- 除文件管理改名外，不改其它工具名 i18n 文案、序号规则、固定/重命名/关闭等标签交互。
- 不改工具描述文案（如「浏览、上传和下载 SSH 文件」）、README/PRODUCT 文档、Go 注释与 `frontend/bindings/`。
- 不改镜像管理、服务管理、SSH 文件管理的来源持久化方式（本来就是标签内选择）。
- 不改网络测试以外的持久化结构，也不动 `default-light` / `default-dark`。
- 不改托盘、命令面板、任务中心里显示的工具名，也不新增标题相关的 i18n 文案。

## 验收标准

- 镜像管理切到 SSH 来源 `box-a` 后，标签显示 `box-a · 镜像管理`；再切回「本机」显示 `镜像管理`；同名标签的第 2 个显示 `box-a · 镜像管理 2`。
- 镜像管理切到 Registry 来源：有名称时显示名称，名称为空时显示 Registry 地址。
- 文件管理、服务管理各自选择远程来源后，标签分别显示 `主机名 · 文件管理`、`主机名 · 服务管理`；选择本机时无主机部分。
- 工具列表、命令面板、页面标题、设置与任务中心里该工具均显示为「文件管理」/`File Manager`，全仓不再有用户可见的「SSH 文件管理」/`SSH Files`/`SSH File Manager`。
- 网络测试：两个标签可以各自选择不同来源并各自显示对应主机名；新开标签默认来源是来源列表首项；配置里不再写入 `sourceID`，旧配置带 `sourceID` 也能正常加载。
- 端口转发标签始终显示 `端口转发`（及序号），无主机部分。
- 来源引用的 SSH 配置被删除后，对应标签回退为纯工具名且不报错。
- 手动重命名过的标签显示自定义名，不带主机部分。
- `go test ./...` 与前端构建通过，`frontend/bindings/` 为重新生成的结果而非手改。
