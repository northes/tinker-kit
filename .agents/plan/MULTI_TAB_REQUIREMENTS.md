# 多 Tab 工作区改造：需求、实施边界与验收

> 状态：需求讨论稿，尚未实施。本文记录已确认的产品决定，并把未逐项讨论的交互细节标为「实施建议」，供编码前确认；不能把建议误当成既有行为。
>
> 范围：Wails 桌面应用的 React 工作区、配置与相关 Go 服务接线。文中的 `tab` 指应用内工作区标签，不是系统窗口或浏览器标签。

## 1. 目标与术语

把当前「侧栏选择一种工具、每种工具常驻一份」改为「一个窗口内有多个工作区 tab」。同一种工具可以打开多份，输入、结果、撤销、局部视图及会话型请求各自独立。应用配置、真实系统资源、任务中心等仍由原有全局边界管理，不复制一套配置或后端。

区分以下三种容易混淆的“历史”：

- **操作历史记录**：`HistoryPage`、`AppendHistory`、历史回填和 `history.json` / `history-data`。本次彻底移除功能，但不处理磁盘上已经存在的历史文件。
- **浏览器前进/后退栈**：不再作为产品导航；移除相应按钮、命令、鼠标/手势接线。
- **工具内部撤销与数据趋势**：例如 `TimeTool` 的 `useHistory`、CodeMirror 撤销、服务指标趋势、任务中心与服务日志；不是要移除的操作历史，继续保留。

### 已确认的产品决定

1. 同一 `ToolId` 可以有多个 tab；每个 tab 的工作数据互不干扰。`ToolId` 表示工具类型，不充当实例 ID。
2. 移除侧栏、前进/后退和整个操作历史功能。旧历史文件不迁移、不删除、不清空，也不再由应用读写。
3. 新建 tab 首先显示 blank 页；用户可在其中选择加载哪种工具。
4. 关闭 tab 直接丢弃该 tab 的临时内容，不弹脏状态确认；重启后不恢复 tab 或 tab 内容。
5. 只有当前前台激活的 tab 能接收文件拖入。
6. 设置中提供托盘填入目标策略：「新开工具 tab」或「填入最近使用的匹配工具 tab」。
7. 镜像详情在发起它的镜像列表 tab **内部**打开，返回同一 tab 的列表。
8. 不在前台的镜像列表 tab 不继续持有镜像 watcher。
9. 网络测试的超时、代理、DNS、TLS、网卡、探测内容等测试参数只在所在 tab 内生效，不再写入持久化 `Config`。

### 实施建议的默认交互

下列细节用于消除实现歧义；如需调整，应在开发前修改本文：

- 启动时只有一个 blank tab；关闭最后一个 tab 后立即生成一个新的 blank tab，不出现无 tab 工作区。
- 点击 `+` 总是新建 blank tab；在 blank 页选工具时**原地加载**，保留 tab ID。已加载工具的 tab 不提供隐式替换工具操作，以免意外丢内容。
- 设置是可关闭的**单例 tab**，由标题栏固定入口、命令面板及现有应用菜单/事件打开；再次打开时激活已有实例。blank 页工具选择器只列工具，不把设置当工具。
- 从非 blank 页执行命令面板的「打开工具」时新建已加载工具的 tab；从 blank 页执行则填充当前 blank tab。当前工具的操作命令作用于当前 `tabId`，不广播到所有同类 tab。
- 「最近」按用户最近激活过的同类工具 tab 计算，而不是创建时间或渲染顺序；没有匹配 tab 时创建已加载工具的新 tab。托盘的「新开」策略始终创建新 tab，不复用已有 blank tab。
- 不再恢复 `devutils.lastPage` 指向的工具；旧 key 可以留在本机，但新版本不读取或继续写入它。不新增别的前端设置 `localStorage`。

## 2. 用户流程与可见行为

| 场景 | 预期行为 |
| --- | --- |
| 首次进入 / 重启应用 | 显示 blank tab 和可搜索/选择的工具列表；没有旧 tab 内容。 |
| 点击 `+` | 在 tab 栏新增并激活 blank tab；此前 tab 原样保留。 |
| blank 页选择工具 | 当前 blank tab 变为对应工具实例；相同工具可在另一 blank tab 再选一次。 |
| 切换 tab | 保留各自编辑内容、结果、撤销与局部滚动/筛选状态；只有当前 tab 可接收键盘、拖入、粘贴及上下文命令。 |
| 关闭 tab | 立即销毁其临时状态，不确认、不写操作历史；激活相邻 tab，最后一个关闭则生成 blank tab。 |
| 打开设置 | 使用同一个设置 tab；全局设置变更按现有数据流通知相关工具实例。 |
| 镜像列表打开详情 | 仅改变当前镜像 tab 的内部视图；另一个镜像 tab 的来源、筛选、选择和详情不变。返回后仍是原列表 tab。 |
| 应用菜单要求打开设置 | 激活/创建设置 tab，不依赖旧侧栏或浏览器路由。 |
| 禁用自动覆盖后托盘命中已有 tab | 先激活并固定目标 tab，再按现有逻辑询问是否填入；确认前目标关闭则取消此次填入，不转移到其他 tab。 |
| 托盘选择新开 tab | 创建已加载工具的新 tab 并填入；由于没有旧内容，建议不弹「覆盖现有内容」确认。 |

tab 栏应处理窄窗口下的溢出、当前 tab 可见性、关闭按钮和 `+` 的可达性。标题栏仍须留出 macOS 窗口按钮与 Wails 可拖拽区域，交互控件本身标记为不可拖拽。使用项目现有组件和 Tailwind 样式；tab 的键盘切换、名称、选中状态、关闭后的焦点落点以及屏幕阅读器语义都要可用。隐藏的 tab 不能保留可达焦点；通过 portal 打开的浮层在切换 tab 时也不能留在别的 tab 上方。

## 3. 状态归属与数据模型

`AppShell` 只拥有 tab 集合、顺序、激活 ID、最近激活顺序，以及跨 tab 入口的派发；各工具组件继续拥有自己的编辑与结果状态。推荐从纯状态转移函数出发，而不是在侧栏、路由、工具中各存一份「当前页」：

```ts
type WorkspaceTab =
  | { id: string; kind: 'blank' }
  | { id: string; kind: 'tool'; toolId: ToolId }
  | { id: string; kind: 'settings' };

type WorkspaceState = {
  tabs: WorkspaceTab[];
  activeTabId: string;
  recentToolTabIds: string[]; // 最近激活优先；只引用仍存在的工具 tab
};
```

这只是状态边界示意，不要求逐字照抄类型。`ToolId` 保持现有联合类型；tab ID 使用稳定且唯一的实例标识。工具局部的 `image-manager` 列表/详情状态不进入全局 `Page`，也不增加一个独立的详情 tab。所有打开/激活/关闭/tab 转换都经同一组动作更新，保持：

- 至少一个 tab，恰有一个激活 tab，`activeTabId` 必须存在于 `tabs`。
- tab ID 在 blank 变工具、隐藏、再激活期间不变；不同实例即使 `ToolId` 相同也不共享 React `key`、编辑器和局部 ref。
- `recentToolTabIds` 不含 blank/设置/已关闭 tab；重复激活同一个 tab 只调整其顺序。
- 应用级配置只有 Go `ConfigService` 一个持久化来源；工具会话内容不写设置配置，也不写前端设置 localStorage。

在 App 边界生成新 ID，并把 ID 作为纯状态转移动作的参数传入；不要在 reducer 中调用随机数或时钟。测试才能用固定 ID 重现相同的关闭、最近激活与异步派发顺序。

将当前按 `Page` 固定写出的单份 `tool-slot` 改为按 tab ID 常驻挂载的实例容器：第一次激活时才加载组件；切到其他 tab 只是隐藏，不卸载。选用 `frontend/src/components/ui/tabs.tsx` 等现有组件时须核实未选中面板是否会卸载；若会卸载，工作区内容另用稳定容器保活。关闭 tab 才真正卸载并清理副作用。设置与 blank 不必以工具方式常驻。

### 精确派发与异步竞态

现有 `PendingAction` 只带 `tool: ToolId`，同类实例会同时消费。新的动作目标必须有 `targetTabId` 和请求序号/标识；只由目标实例消费并清除自己的动作。命令面板、托盘识别、打开文件、设置入口等都先决定目标 ID，再发送动作；若异步读取剪贴板或显示确认框期间目标已关闭，取消该动作，不重新选择另一个 tab。后到的旧回调不得覆盖目标 tab 更新后的内容。

命令面板的分组、拼音/首字母检索继续沿用现有机制，但「当前工具命令」须依据**激活 tab 的工具类型和该实例上下文**过滤；JSON Schema/Pipeline 等当前通过全局事件通知的上下文不能被隐藏的同类 tab 覆盖。外部 `navigate` 事件（特别是打开设置）应映射到 tab 操作，不创建第二套页面状态。

## 4. 托盘填入的明确规则

在 Go `Config` 新增一个有界枚举值（建议 `trayFillTarget: 'new-tab' | 'recent-tab'`），由设置页维护、Go 负责默认值与非法值归一化；旧配置缺字段时建议默认 `recent-tab`，以接近旧版复用工具页的行为。两种策略都先走已有的内容识别和可匹配工具开关：

1. `new-tab`：新建已加载目标工具的 tab，激活后只发给新实例。
2. `recent-tab`：从仍打开的同类工具 tab 中取最近**激活**的实例；若没有则同 `new-tab`。
3. 命中 Diff 时保留已有「填入之前/之后/交替」设置，但「交替」的下一目标属于被选中的 Diff **实例**，不应由全应用一个 ref 让多个 Diff tab 互相改变。
4. 复用已有实例时尊重现有 `autoOverwrite`：允许覆盖则直接填，关闭自动覆盖则激活目标、预览并确认。目标关闭、实例类型变化或请求失效时取消确认。新建实例没有要覆盖的内容，建议直接填入。
5. 禁止向隐藏 tab 静默写入：目标在填入前成为激活 tab。若确认弹窗出现后用户切走或切回，仍只允许按已锁定的 ID 完成或取消，不重新计算「最近」。

侧栏的「工具禁用/排序」不再决定工具是否能在 blank 页选择，也不再过滤托盘识别。托盘是否识别某工具只由 `trayMatchTools` 及对应功能设置决定；移除 `SettingsPage` 和 `App.tsx` 对 `sidebarTools` 的隐式依赖。

## 5. 工具与后端生命周期

### 镜像列表和详情

目前 `ImageManagerTool` 与 `ImageManagerDetailPage` 在 `App.tsx` 是两套页面挂载。改为每个镜像工具 tab 自己保存 `{ sourceId, imageId } | null` 的详情视图状态；列表在该 tab 内保持挂载，详情按该 tab 的来源和镜像 ID 加载。详情「返回」只清除此状态，不使用 `routerNavigate(-1)`。若详情异步响应晚于切换镜像/关闭 tab，不能显示到另一实例。

Go 的 `ImageService.WatchDockerImages` 在服务内只有一个 `watchWorker`：新的 watch 会取消旧 run。因此 watcher 的**资格由激活的镜像 tab 独占**；切走时取消该 tab 的 watch 并解除事件订阅，切回时为该 tab 的当前来源重新建立 watch。前台 tab 即使正在看本 tab 的镜像详情，也仍算激活，列表是否可见和 tab 是否激活不可复用同一个布尔量。镜像导出、拉取等已交给 Go 的长期任务及全局任务中心不因此取消。

现有 watcher effect 启动时会清空 `images` 和 `selected`。必须将「来源真的变了」与「只是失活后重连」分开：失活保留该 tab 的快照、选择、筛选；重连前可标示数据正在刷新，但不能把旧快照当作最新结果；拿到新一轮完整快照后按 ID 核对选择并移除已消失项。来源改变才重置来源相关状态。事件继续按 `clientID`、`sourceID`、`generation`、`revision` 校验，过期 watch 的事件不得污染当前实例。多个镜像 tab 监听全局任务快照时不能产生重复通知。

### 网络测试和其他工具

`NetworkTestTool` 的测试参数从固定默认值初始化，局部保存至所属 tab；移除 `GetNetworkTestSettings`、`SaveNetworkTestSettings`、Go `Config.NetworkTestSettings` 及其默认化、归一化、保存覆盖保护和导入/导出接线。超时与 payload 等虽然目前不都放在「高级」折叠区，仍属于同一份 tab 局部请求参数；不要留半套持久化。旧配置字段可在新版本读取时忽略，不迁移到 tab；修改 Go 导出类型后通过项目任务重新生成 bindings，禁止手工编辑 `frontend/bindings/`。

网络测试进度本已按 `runID` 筛选，仍需保证两份网络测试 tab 同时运行、各自取消与展示结果互不串线。切到别的 tab 时会话型请求可继续，以便切回来查看；**关闭**该 tab 则取消其可取消的请求并忽略晚到回调。对 SSH 文件、镜像、服务等工具逐项区分「随视图取消的查询/watch」和「已交给后端持续执行的任务」：后者继续在任务中心可见。共享的镜像、端口、SSH 来源或主题发生真实变化时，各 tab 应正确刷新；这些全局资源不被复制成 per-tab 设置。

### 拖入、粘贴、DOM 与浮层

所有 `useFileDrop` 的 `enabled` 都应取决于所属 tab 是否激活且接收容器是否可见；`id` 必须包含 tab ID，不能复用当前按工具写死的 `*-drop-zone`。Wails 的 `files-dropped` 事件仍按原来的目标 ID 匹配。剪贴板文件粘贴的 window 监听也仅在活动工具启用。重复挂载后检查固定 HTML `id`、`htmlFor`、`aria-describedby`、ResizablePanelGroup ID、DOM 查询及 window 事件：改为实例唯一或限定在该 tab 根节点作用域。仅靠 CSS 把旧 tab 设为不可见，不能防止其消费全局事件或 portal 浮层抢焦点。

## 6. 移除侧栏、历史和前进/后退

按直接生产者/消费者分批清理，避免留下半套无效行为：

| 边界 | 变更 |
| --- | --- |
| `frontend/src/App.tsx` | 移除 `Sidebar`、管理/排序、按页 `visited` 和固定工具槽；移除浏览器前进后退按钮、历史页路由、相关命令及 `historyIndex`；改成 tab 集合与唯一的活动 tab。 |
| `frontend/src/components/SettingsPage.tsx` | 移除侧栏管理和清空历史设置；保留应用配置与托盘识别，新增托盘填入目标模式；解除托盘工具与侧栏启用项的联动。 |
| 各工具、`HistoryPage.tsx` | 移除 `record` 属性、`AppendHistory` 调用与历史恢复动作/页面；不要误删工具自身撤销、任务状态、服务日志或指标趋势。 |
| `configservice.go` 与相应测试 | 停止读取、记录和写入操作历史；移除不再暴露的历史 API、模型及历史专用测试。已有 `history.json`、`history-data` 留在原位，不做文件清理、迁移或启动时报错。清理侧栏和网络测试失效配置，保留与新版本配置兼容的默认化。 |
| `main.go`、macOS 鼠标导航接线 | 不再启用 WebKit 前进后退手势、鼠标侧键和本地 swipe 到 `mouse:navigate` 的映射；不影响正常拖窗、文件拖入、任务通知或应用菜单。 |
| locale / bindings | 中英 locale 同步增删用户可见文案；Go 导出类型变化后用 `wails3 task common:generate:bindings` 生成 bindings。 |

`react-router` 若仍用于启动入口或已有外部链接，不能再维护一份与 tab 状态并列的当前页面或可回退历史栈；旧 `/#/<tool>` 链接如需兼容，只能在入口解析成「新开一个该工具 tab」的意图。确定是否存在对外深链消费者后，再决定保留最薄的入口解析还是移除路由。`devutils.lastPage` 不再参与启动选择；不能替换成另一种前端本地设置键。

Go 配置中的旧 `sidebarMode`、`sidebarTools` 和 `networkTestSettings` 不应继续影响新界面；旧配置载入/保存不得导致其他有效设置（主题值 `default-light` / `default-dark`、语言、来源、托盘开关等）丢失。历史文件和配置文件是两回事：可以按新配置模型写回配置，但**不能借移除功能删除历史文件**。

## 7. 建议实施顺序

1. 抽出纯 tab 状态转移与动作定向规则，先写单元测试；明确 blank、设置单例、关闭最后一个、最近实例的行为。
2. 搭建 tab 栏和按 `tabId` 保活的工具渲染边界，把镜像详情收进所属 tab；接入标题栏、设置和命令面板入口。
3. 把所有 `PendingAction`、托盘填入、文件拖入、剪贴板、全局上下文事件改为只命中目标实例；盘点每个工具的固定 DOM ID 与异步副作用。
4. 将镜像 watch 改成仅激活 tab 持有，重连不清空快照；按工具检查关闭清理和后台持久任务边界。
5. 移除操作历史、侧栏与前进后退的前后端接线；调整 `Config`，重新生成 bindings 并同步中英 locale。
6. 通过单元测试、构建、Go 测试及 Wails 桌面手工验收，再检查旧历史文件未被触碰和新旧配置导入行为。

每一步只保留一个状态来源；不要为了兼容旧 UI 再维护一份隐藏侧栏/路由页面。与本需求无关的网络协议功能改动独立审查，不并入本改造。

## 8. 单元测试如何写

### 前端纯逻辑测试

项目目前没有 Vitest/Jest；已有 `frontend/src/lib/*.test.mjs` 使用 `node:test`、`node:assert/strict`，通过 Node 的 TypeScript strip-types 直接导入无 DOM 的 `.ts` 逻辑。建议把 tab reducer/状态转移、最近目标选择、托盘目标决策抽到 `frontend/src/lib/` 的纯函数，在同目录加 `workspace-tabs.test.mjs`、`tray-target.test.mjs`，并在根 `Taskfile.yml` 增加 `test:tabs`，由 `wails3 task test:tabs` 执行。测试用固定 tab ID、明确的动作顺序和内存快照断言结果；不要为了测试把 React 状态复制到第二个 store。新任务可按现有 `test:image-tasks` 模式配置：

```yaml
test:tabs:
  summary: Checks workspace tab and tray targeting rules
  cmds:
    - node --experimental-strip-types --test frontend/src/lib/workspace-tabs.test.mjs frontend/src/lib/tray-target.test.mjs
```

| 测试 | 准备与断言 |
| --- | --- |
| 初始与 blank 转工具 | 初始恰好一个激活 blank；选择工具后 tab ID 不变、类型正确，再点 `+` 为新 blank。 |
| 同类重复与隔离 | 生成两个同类 `ToolId`、不同 tab ID；激活、关闭或定向动作只改变目标实例的元数据/队列。工具内部输入的隔离由组件边界验收。 |
| 关闭相邻/最后一个 | 关闭活动 tab 后激活预期邻居，最近列表清理旧 ID；最后一个关闭后生成新的 blank ID；关闭非活动 tab 不切走当前 tab。 |
| 设置单例 | 连续打开设置只返回同一个设置 tab；关闭后再次打开创建新 ID。 |
| 最近匹配 | 激活顺序 A(json) → B(json) → C(text) 后匹配 json 为 B；关闭 B 后为 A；无匹配时产生「新建」决策。 |
| 托盘两种模式 | `new-tab` 从不选择已有实例；`recent-tab` 只选仍存在的同类 tab；目标在等待确认期间关闭则动作为取消，不改投其他实例。 |
| 异步动作序号 | 旧请求晚到、目标已关闭或已重新初始化时不清除/覆盖新动作；不同同类 tab 各消费自己的请求。 |
| Diff 交替 | 两个 Diff tab 分别维持 before/after 下一目标，新建实例从默认位置开始。 |
| watcher 事件定向 | 对活动镜像 tab 只接受匹配当前 `clientID`、`sourceID`、generation/revision 的事件；切走、切回后旧 client 的晚到事件不改变新快照。 |
| 配置归一化 | 新字段缺失/非法恢复默认值；已有 `trayMatchTools` 的显式关闭和合法项不因旧侧栏配置被改写。 |

测试应直接断言状态和事件目标，不用时间延迟或 DOM 选择器猜测。对纯逻辑难覆盖的全局监听、portal 和编辑器实例，若后续引入组件测试运行器，先补针对「两个相同工具挂载，只活动实例接收事件」的集成测试；当前不把没有运行器的测试伪装成已覆盖。

### Go 单元测试

在 `configservice_test.go` 用临时配置目录覆盖：新 `trayFillTarget` 默认值、合法值保存/重载、非法值回退、旧配置缺字段导入、旧侧栏/网络测试字段不影响有效配置。历史移除后删除或改写当前依赖 `AppendHistory` 的测试；增加「存在旧历史文件时初始化/保存配置不会改写或删除该文件」的回归测试，**只在测试临时目录写模拟历史文件**。

`imagesync_test.go` 已覆盖单 worker 的部分行为；仅在服务逻辑实际改动时增加或调整「A client watch → 取消 → B client watch，同一时刻只有 B worker 活跃、B 事件保留 B 的 clientID」的测试。A 事件晚到时是否影响 B、前端保留快照/筛选/选中项属于前端边界，应由前端纯逻辑测试及桌面验收覆盖，不拿 Go 测试冒充验证。

### 验证命令

具体任务以根 `Taskfile.yml` 为准：实现后运行 `wails3 task test:tabs`（新增任务）、`wails3 task test:go`、`wails3 task common:build:frontend`，最后按发布目标运行 `wails3 task build`；Go 导出签名变动先运行 `wails3 task common:generate:bindings`。检查 `git diff --check` 和生成文件 diff。新任务若尚未加入，不能声称已经运行过它。

## 9. Wails 桌面手工验收清单

项目规则不允许用 Playwright、`playwright-cli`、Computer Use 或浏览器自动化验证；下列流程在 `wails3 task dev` 启动的真实桌面应用中人工执行，并记录平台及结果。

1. 启动是 blank；打开两个 JSON（以及两份网络测试）tab，分别编辑、撤销、切换，内容和命令互不串线；关闭其中之一，另一个仍可用；关闭最后一个回到 blank，重启不恢复旧 tab。
2. blank 页工具列表可发现全部工具；命令面板从 blank 加载到原 tab、从已加载 tab 新开实例；设置按钮、命令、应用菜单均聚焦同一设置 tab；无侧栏/历史/前进后退残留入口，鼠标侧键和 macOS 滑动不会触发错误导航。
3. 在两个同类支持拖入的 tab 间切换，仅前台可收 Wails 文件拖入及剪贴板文件粘贴；拖入目标 ID 唯一，隐藏页不会弹对话框、写入内容或抢焦点。
4. 托盘选 `new-tab` 时每次填入新实例；选 `recent-tab` 时填入最近激活的匹配实例，无匹配时新建；自动覆盖关闭时确认只作用于事先锁定的实例，确认期间关闭目标不会误填另一 tab；测试两个 Diff tab 的交替填入。
5. 两个镜像列表 tab 选不同来源/筛选/镜像，打开其中一个的详情再返回，彼此视图不变；切走停止旧 watcher，切回可看到保留的列表和选择并刷新真实变化。快速切换 A→B→A，只有前台 watch 接收新事件，不出现旧事件串线或重复提示。
6. 镜像导出/拉取、SSH 文件等持久后台任务在切走/关闭视图后仍能在任务中心完成；网络测试等会话型操作在关闭所属 tab 后停止或忽略回调，两份测试可并发且结果按 runID 隔离。
7. 修改网络测试参数，仅影响本 tab；关闭重开/重启回默认值，不再写入 Config；其余全局设置和数据源仍按现有机制持久化。
8. 启动前在测试环境准备旧操作历史文件，使用应用、修改设置、退出后文件内容与时间戳保持不变；应用不再新增历史记录，工具内部撤销、任务中心、服务日志和指标趋势仍工作。
9. 检查最小窗口尺寸、tab 栏溢出、macOS 标题栏拖拽和窗口控制、键盘焦点/屏幕阅读器标签，以及中英文文案。

验收以实际目标行为为准；编译通过、单元测试通过都不能替代多实例、原生文件拖入和 watcher 生命周期的桌面验证。

## 10. 完成标准

- 所有已注册工具可在同一窗口多开；相同 `ToolId` 的实例状态和命令派发严格隔离。
- 无侧栏、浏览器前进/后退和操作历史功能残留；旧历史文件不受影响，其他“历史”语义未被误删。
- 托盘模式、blank、设置单例、镜像详情、激活态拖入及网络测试 tab 内参数符合本文规则。
- 同一时刻仅前台镜像 tab 持有镜像 watcher；失活不丢快照，重连后数据正确；全局任务仍有明确归属。
- 前端纯逻辑测试、相关 Go 测试、项目构建和真实 Wails 桌面验收均有记录；Go bindings 由任务生成，两个 locale 同步。
